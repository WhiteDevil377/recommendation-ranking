# Experiment specification

Recorded before model-quality evaluation on 9 November 2026.

- Dataset: stable MovieLens 1M, 1,000,209 ratings. Use ratings and movie metadata only; do not load demographic data. Do not redistribute the source data or trained profile matrices in the public repository.
- Task: rank unseen movies using binary positive preferences derived from ratings >=4. This is an offline preference benchmark, not observed implicit consumption or causal business impact.
- Split: per-user positive-event timestamp cutoffs at positions floor(0.8*n) and floor(0.9*n). Assign all timestamp ties to the later block. Evaluate users with >=20 positive ratings and strict nonempty train/validation/test blocks, with >=5 training positives. Training for those users uses only events before the validation cutoff. Ineligible users contribute their available positives to training but are excluded from ranking metrics and counted in the audit.
- This is a per-user temporal, transductive benchmark. It is not a global chronological deployment simulation: another user's training events may be later than a given user's held-out events. All catalogue movie IDs are available as a static catalogue. Preserve cold-item holdouts in the denominator and report them.
- Positive training matrix and all-rating seen-item filter are distinct. Mask any item a user rated before their cutoff, including low ratings. Keep the training model and this filter frozen through validation and test; no intermediate retraining on validation events.
- Fixed candidates: popularity; cosine item-neighbour models with 50/100 neighbours and co-occurrence shrinkage 10; weighted implicit ALS with (factors,alpha)=(32,20),(64,20),(64,40), regularization=0.1, 10 iterations, seed 42. Implement ALS updates from the published weighted normal equations and verify objective descent.
- Select one method by mean validation nDCG@10 across eligible users, then freeze before computing test comparisons. Evaluate all six fixed candidates on the full catalogue with nDCG@10, Recall@10, MRR@10, and catalogue coverage. Do not use sampled negatives for headline metrics.
- For the selected model, compare test nDCG@10 with popularity using 1,000 paired user-bootstrap resamples, seed 2026. The interval is conditional on the fixed fitted models and this benchmark; it is not an external-data guarantee.
- Diagnostic only: compare the selected model's full-catalogue test metrics with a candidate set containing each user's positives and 100 fixed randomly sampled nonrelevant, unseen movies. Calculate this after method selection and report the protocol difference clearly.
- Performance: compare one-user-at-a-time full sorting with batched scoring and partial top-k selection. Same selected model, 1,000 fixed sampled eligible users, k=10, batch_size=64, two CPU threads, warm process, seven repetitions in alternating execution order. Check Top-10 list agreement and numerical score differences. Report median, p95, and speed ratio; include no model loading, HTTP overhead, or production-throughput claim.
- Provide a local recommendation API, cold-user popularity fallback, input validation, and correctness checks against dense toy mathematics and ranking reference cases.
- No novel-algorithm, state-of-the-art, independent-authorship, hiring guarantee, large-scale production deployment, commercial permission, or online revenue/uplift claim.
